# Beekeeper of Ukraine — інтернет-магазин

Магазин продуктів бджільництва: мультимагазинні ціни й залишки, ролі (адмін/продавець/автор/покупець),
акції та промокоди, перевірка дипломів, редагований контент, PWA-адмінка з мобільного, сповіщення
Telegram / Email / Web Push, автоматичне SEO (sitemap, JSON-LD, OG-теги).

Чистий PHP 8.1+ без залежностей — працює на XAMPP і на shared-хостингу HostIQ простим копіюванням.

## Запуск на ПК (XAMPP + Docker)

1. **Запустіть XAMPP** (Apache).
2. **Запустіть базу** — у папці `C:\xampp\htdocs\bofu` виконайте в командному рядку:
   ```
   docker compose up -d
   ```
   Перший запуск завантажить MySQL (~1 хв). База слухає порт **3307**, дані зберігаються у Docker-томі.
3. Відкрийте **http://localhost/bofu/** — при першому відкритті сайт сам створить таблиці й демо-дані.

**Демо-вхід:** кнопка «Увійти» → «Увійти як адміністратор / продавець / покупець».

phpMyAdmin для бази: **http://localhost:8081** (bofu / bofu_secret).

## Структура

```
index.php          — точка входу (весь трафік через неї)
config.php         — конфігурація за замовчуванням (не редагувати)
config.local.php   — ваші локальні перевизначення (створіть за потреби)
app/Core           — ядро: роутер, БД, шаблони, авторизація, сповіщення, WebPush
app/Controllers    — логіка сторінок (вітрина + адмінка)
app/Views          — шаблони
assets/            — стилі, шрифти, зображення, завантажені фото (uploads/)
bin/cli.php        — консольні команди: migrate | seed | fresh
storage/           — логи, сесії (не публікується)
```

## Замовлення з кількох магазинів

Одне замовлення покупця автоматично розкладається на **підзамовлення** — по одному на магазин,
який реально виконує позиції. Так один продавець не бачить чужої роботи, а покупець має одне
замовлення з одним номером.

```
BOFU-260801-A3F2       головне: контакти, доставка, промокод, сума, зведений статус
├── BOFU-260801-A3F2/1  Магазин №1 — свої позиції, свій статус, свій продавець
└── BOFU-260801-A3F2/2  Магазин №2 — …
```

- **Хто виконує позицію** визначається при оформленні: самовивіз — обраний магазин; інакше той,
  де вистачає залишку на всю кількість (далі — де хоч щось є, і як запасний — магазин за
  замовчуванням, для товарів «під замовлення»). Залишки списуються саме з нього.
- **Підзамовлення створюється завжди**, навіть коли магазин один. Тоді передача позиції іншому
  магазину нічого не перебудовує, а доступи, сповіщення й статуси працюють одним шляхом.
- **Статус головного рахується сам**: він дорівнює найменш просунутій частині. Щойно всі магазини
  поставили «Доставлено» — головне стає «Доставлено» без ручних дій. Усі скасовані → скасовано.
  Адмін може проставити статус усім частинам одразу з картки головного замовлення.
- **Передача позиції в інший магазин** (адмінка → Замовлення → кнопка «→» біля позиції): позиція
  переїжджає в підзамовлення того магазину (створюється, якщо його ще не було), залишок повертається
  старому магазину й списується в нового, новий продавець отримує сповіщення. **Ціна не змінюється** —
  покупець платить рівно те, що бачив у кошику. Підзамовлення, що лишилось без позицій, закривається.
- **Продавець** бачить у списку лише свої частини, але може відкрити замовлення цілком: контакти,
  доставку й те, які магазини ведуть решту частин (без права їх змінювати).
- Уся історія — розділення, зміни статусів, передачі — пишеться в `order_events` і показується
  на сторінці замовлення.

Технічно: обидва рівні лежать в одній таблиці `orders` (`parent_id` = головне, `seq` = номер частини),
позиції `order_items` — **тільки** в підзамовленнях. Логіка зібрана в `app/Core/OrderFlow.php`.

## Налаштування інтеграцій (адмінка → Налаштування)

- **Google OAuth**: Google Cloud Console → Credentials → OAuth Client ID (Web).
  Redirect URI показано на сторінці налаштувань. Поки ключів немає — працює демо-вхід.
- **Telegram**: створіть бота у @BotFather → вставте токен. Кожному продавцю/адміну впишіть
  його Chat ID (адмінка → Користувачі). Сповіщення про нові замовлення прийдуть у Telegram.
- **Нова Пошта**: API-ключ з кабінету novaposhta.ua → автопідказки міст і відділень у checkout.
- **Web Push**: ключі генеруються автоматично; на телефоні запрацює після переносу на HTTPS.
- **Розсилка** (адмінка → Розсилка): адреси збираються лише за явною галкою згоди — при оформленні
  замовлення або в профілі. Експорт CSV містить колонку `unsubscribe_url` — це персональне посилання
  на відписку, яке **обовʼязково** треба вставляти в кожен лист розсилки.
- **Демо-вхід вимкнений за замовчуванням** (він дає адмін-права одним кліком без пароля).
  Щоб увімкнути його *локально*, поки не налаштовано Google/Telegram, — у `config.local.php`:
  ```php
  <?php return ['demo_login' => true];
  ```
  На бойовому сервері не вмикайте: цей рядок = відкрита адмінка для будь-кого.

## Безпека

- Ціни, знижки й підсумок рахуються **тільки на сервері** з БД. З браузера приймаються лише
  `product_id`, `variant_id`, `qty` — підмінити ціну через POST або DevTools неможливо.
- **Ролі.** Адмін веде сайт цілком. Продавцю доступні лише замовлення його магазинів та
  **ціни й залишки цих магазинів**; картку товару (назва, опис, базова ціна, варіанти, фото),
  медіа-бібліотеку, налаштування, користувачів, акції та контент змінює лише адмін.
  Перевірка — на сервері (`Products::save()`, `Auth::requireAdmin()`), форма її лише повторює.
- **Доступ до точки закінчується разом із роллю.** Прив'язка людини до магазину
  (`seller_stores`) існує лише поки в неї є роль продавця: знімають роль — вона зникає з усіх
  точок, і повернення ролі доступу **не відновлює**, магазини треба призначити наново
  (`Users::saveStores()`). Інакше рядок прив'язки пережив би звільнення й одна галка,
  повернена через рік зовсім для іншої точки, мовчки відкрила б старі залишки й замовлення.
- **Файли поза доступом ззовні**: `app/`, `bin/`, `storage/` (сесії, логи, SQLite) і `config*.php`
  закриті власними `.htaccess` — вони працюють навіть якщо `mod_rewrite` вимкнений.
  У `assets/uploads/` заборонено віддавати скрипти; фото ще й перекодовуються через GD.
- Дані, що потрапляють усередину `<script>` (JSON-LD, варіанти товару), виводяться через
  `json_js()` — назва товару з `</script>` не може розірвати тег.
- Обовʼязковий телефон: номер нормалізується до `+380XXXXXXXXX` (або E.164), сміття не проходить.
- Сторінка «замовлення прийнято» відкривається за випадковим токеном, а не за номером замовлення.
- Обмеження частоти (таблиця `rate_hits`, за IP): оформлення 15/год, вхід через месенджер 20/год,
  код на телефон 10/год, довідник Нової Пошти 300/год, перевірка диплома 40/год. У формі checkout
  є honeypot-поле для ботів.
- **За Cloudflare або балансувальником** увімкніть у `config.local.php` `'trust_proxy' => true`,
  інакше всі відвідувачі рахуватимуться як один IP. Без проксі лишайте `false` — інакше ліміт
  обходиться підробкою заголовка `X-Forwarded-For`.

## PWA (додаток на телефон)

Відкрийте адмінку на телефоні → меню браузера → «Додати на головний екран».
Кнопки «Встановити додаток» і «Увімкнути пуші» є в бічному меню адмінки.

## Перенос на HostIQ (коли буде готово)

1. Експортуйте базу: `docker exec bofu-mysql mysqldump -ubofu -pbofu_secret bofu > dump.sql`
2. У cPanel створіть базу MySQL і імпортуйте dump.sql через phpMyAdmin.
3. Скопіюйте файли проєкту в `public_html` (FTP або File Manager).
4. Створіть `config.local.php` з доступами до бази хостингу:
   ```php
   <?php return ['db' => ['host' => 'localhost', 'port' => 3306,
     'database' => 'xxx_bofu', 'username' => 'xxx_user', 'password' => '...']];
   ```
   Демо-вхід тут не вмикайте — за замовчуванням він вимкнений, і так і має лишитися.
5. Увімкніть SSL (безкоштовний у HostIQ) — запрацюють Web Push і Google OAuth.
6. Перевірте, що `https://ваш-домен/config.php`, `/storage/`, `/app/` віддають 403 —
   якщо ні, у хостингу вимкнений `AllowOverride` і `.htaccess` не діють.
